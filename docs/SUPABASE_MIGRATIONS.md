For a new project, follow [the current setup guide](../START-HERE-ARCHIVE-DELETE.md). Choose the single SQL installer or the project-pinned CLI. Do not apply the same migration files manually after using the complete installer.

The launcher now invokes the installed CLI's JavaScript entry with Node, so a global `supabase` command and Windows command shims are unnecessary.

```sh
npm run db:login
npm run db:link -- --project-ref YOUR_CONFIRMED_REFERENCE
npm run db:check
npm run db:migrate
npm run db:status
npm run db:types
```

`db:migrate` asks you to confirm the linked reference. `db:check` is a dry run. No old `.temp` project link is shipped. Keep applied migrations immutable: this release leaves the original 16 files unchanged and adds `20261014120000_record_lifecycle.sql`.

The installer in `supabase/setup/NEW_DATABASE_SETUP.sql` is generated by `npm run db:bundle`. It runs all 17 migrations in one transaction, marks their versions in Supabase migration history and rejects an already-installed application. It never drops an existing app as a setup shortcut.

For a disposable local Supabase stack, use Docker and the installed CLI to start it, then `npm run db:migrate -- --local`. `npm run test:sql` uses isolated in-memory PostgreSQL and does not connect to your configured project. Never repair migration history blindly; inspect `db:status` and the actual error first.

=======
Apply supabase/migrations in filename order. These initial migrations were refined before any external installation. After your first installation, keep applied files immutable and append forward migrations.

Install the official Supabase CLI on PATH using its current OS-specific instructions. Confirm `supabase --version`. The cross-platform scripts invoke the CLI directly and never download an unpinned executable at runtime.

```sh
supabase login
supabase link --project-ref YOUR_CONFIRMED_REFERENCE
supabase db push --linked --dry-run
npm run db:migrate
npm run db:types
```

Remote scripts require interactive project-reference confirmation. Use a private secure prompt for database administration credentials, not a saved credential-bearing command. Web runtime credentials do not substitute for migration permissions.

For local disposable Supabase, start Docker then run `supabase start`, `npm run db:migrate -- --local`, `npm run db:types -- --local` and `npm run db:test -- --local`. Never run reset against live data. Compare migration history before attempting any repair.

`schema:snapshot` generates SQL row types and data dictionaries from actually applied migrations in isolated PostgreSQL. These are not claimed as hosted-generated Supabase client types. `db:types` writes shared/generated/database.types.ts from the selected real Supabase schema. Numeric Data API columns are generally numbers; application financial RPCs explicitly return decimal strings.
